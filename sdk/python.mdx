## Installation

```bash
pip install --upgrade pangram-sdk
```

<Note>
SDK 1.1.0 adds native [image](/api-reference/image-detection) and [video](/api-reference/video-detection) methods alongside text, document extraction, bulk, and plagiarism. Upgrade the SDK to use the media methods below.
</Note>

## Pangram

The main client class for interacting with the Pangram Labs API.

`PangramText` remains available for legacy imports, but `Pangram` is the recommended client name.

### Constructor

```python
from pangram import Pangram

client = Pangram(api_key="your-api-key")
```

<ParamField body="api_key" type="string">
  Your API key for Pangram Labs. If not provided, the `PANGRAM_API_KEY` environment variable will be used.
</ParamField>

Raises `ValueError` if the API key is not provided and not set in the environment.

<Note>
`pangram-4` selects the Pangram 4 text series, and `pangram-image-1` selects the Image 1 series. Minor versions can change within the selected series without changing the selector. Read the result's `version` field to identify the model version used; image results determined solely by validated provenance have `version=None`.
</Note>

### predict_image()

Submit one image and wait for its analysis.

```python
result = client.predict_image(
    "image.png",
    model="pangram-image-1",  # Or "pangram-image-flash-1".
    timeout=300,
    poll_interval=0.5,
)
print(result["prediction"], result["ai_likelihood"])
```

**Parameters**

<ParamField body="image" type="str | PathLike | bytes | bytearray | BinaryIO" required>
  Image path, raw bytes, or an open binary file, up to 32 MiB. Strings are paths. The SDK handles base64 encoding. Caller-owned files remain open and are read from their current position.
</ParamField>

<ParamField body="model" type="string" required>
  Required keyword-only selector: `pangram-image-1`, `pangram-image-flash-1`, `pangram-image-0.2`, or `default` (currently Image 0.2).
</ParamField>

<ParamField body="timeout" type="float" default="300">
  Keyword-only timeout in seconds for submission and polling combined. Must be positive and finite.
</ParamField>

<ParamField body="poll_interval" type="float" default="0.5">
  Keyword-only delay in seconds between status requests. Must be positive and finite; values below `0.1` are clamped to `0.1`.
</ParamField>

**Returns**

An `ImageResult` dictionary after successful analysis:

<ResponseField name="task_id" type="string">
  The accepted task ID.
</ResponseField>

<ResponseField name="stage" type="string">
  `STAGE_SUCCESS`.
</ResponseField>

<ResponseField name="prediction" type="string">
  One of `AI Detected`, `Likely AI`, `Unsure`, `Likely No AI`, `No AI`, or `Partially AI`.
</ResponseField>

<ResponseField name="ai_likelihood" type="float | None">
  Model score from 0 to 1; `None` for a provenance-only result.
</ResponseField>

<ResponseField name="confidence" type="string | None">
  `Low`, `Medium`, or `High`; `None` for a provenance-only result.
</ResponseField>

<ResponseField name="detection_source" type="string">
  `model` for model inference or `c2pa` when validated content provenance determines the result.
</ResponseField>

<ResponseField name="version" type="string | None">
  Image model display version, such as `Pangram Image 1.0`; `None` for a provenance-only result.
</ResponseField>

<ResponseField name="heatmap" type="dict | None">
  Patch scores in `grid` and their input-pixel spacing in `patch_stride`; `None` for a provenance-only result.
</ResponseField>

<ResponseField name="metadata" type="dict">
  Content provenance (C2PA), software, and camera metadata when available.
</ResponseField>

<ResponseField name="thumbnail" type="dict | None">
  Metadata-stripped JPEG `data_url`, `width`, and `height`, or `None`.
</ResponseField>

### submit_image()

Submit one image and receive a task ID.

```python
task = client.submit_image("image.png", model="pangram-image-1", timeout=60)
image_task_id = task["task_id"]
```

**Parameters**

<ParamField body="image" type="str | PathLike | bytes | bytearray | BinaryIO" required>
  Image path, raw bytes, or an open binary file, up to 32 MiB. Strings are paths. The SDK handles base64 encoding. Caller-owned files remain open and are read from their current position.
</ParamField>

<ParamField body="model" type="string" required>
  Required keyword-only selector: `pangram-image-1`, `pangram-image-flash-1`, `pangram-image-0.2`, or `default` (currently Image 0.2).
</ParamField>

<ParamField body="timeout" type="float" default="60">
  Keyword-only timeout in seconds for the submission request. Must be positive and finite.
</ParamField>

**Returns**

A `MediaTaskSubmission` dictionary without polling:

<ResponseField name="task_id" type="string">
  The accepted task UUID. Save it to retrieve status or wait for the result. Submission is sent once, with no automatic retry.
</ResponseField>

### get_image_status()

Retrieve the current task status with one request.

```python
status = client.get_image_status(image_task_id, timeout=10)
```

**Parameters**

<ParamField body="task_id" type="string" required>
  The UUID returned by `submit_image()`.
</ParamField>

<ParamField body="timeout" type="float" default="10">
  Keyword-only timeout in seconds for the status request. Must be positive and finite.
</ParamField>

**Returns**

An `ImageTaskStatus` dictionary containing `task_id` and `stage`. Processing stages are `STAGE_IMAGE_INFERENCE` and `STAGE_IMAGE_FINALIZING`. A successful task includes the `ImageResult` fields described under `predict_image()`; a failed task has `stage="STAGE_FAILED"` and an `error` object with `error`, `error_code`, and `retryable`. This method returns failed task statuses without raising `MediaTaskError`.

### wait_for_image()

Poll an existing task until analysis completes.

```python
result = client.wait_for_image(image_task_id, timeout=300, poll_interval=0.5)
```

**Parameters**

<ParamField body="task_id" type="string" required>
  The UUID returned by `submit_image()`.
</ParamField>

<ParamField body="timeout" type="float" default="300">
  Keyword-only timeout in seconds for polling. Must be positive and finite.
</ParamField>

<ParamField body="poll_interval" type="float" default="0.5">
  Keyword-only delay in seconds between status requests. Must be positive and finite; values below `0.1` are clamped to `0.1`.
</ParamField>

**Returns**

An `ImageResult` dictionary with the same fields as `predict_image()`.

A failed task raises `MediaTaskError`, with `task_id` and `error` attributes. A timeout raises `MediaTaskTimeout`, with the accepted `task_id` available for resuming.

### predict_video()

Upload one video and wait for its analysis.

```python
result = client.predict_video("clip.mp4", timeout=600, poll_interval=1)
print(result["headline"], result["prediction_short"])
```

**Parameters**

<ParamField body="video" type="str | PathLike | bytes | bytearray | BinaryIO" required>
  MP4, MOV, or WebM path, raw bytes, or a seekable binary file, up to 500 MiB. Paths stream from disk. Caller-owned files remain open and are read from their current position.
</ParamField>

<ParamField body="filename" type="string | None" default="None">
  Keyword-only upload filename, including its `.mp4`, `.mov`, or `.webm` extension. Required for bytes or an unnamed stream; otherwise inferred from the file.
</ParamField>

<ParamField body="timeout" type="float" default="600">
  Keyword-only timeout in seconds for submission and polling combined. Must be positive and finite.
</ParamField>

<ParamField body="poll_interval" type="float" default="1">
  Keyword-only delay in seconds between status requests. Must be positive and finite; values below `0.1` are clamped to `0.1`.
</ParamField>

**Returns**

A `VideoResult` dictionary using response schema `1.1`:

<ResponseField name="task_id" type="string">
  The accepted task ID.
</ResponseField>

<ResponseField name="stage" type="string">
  `STAGE_SUCCESS`.
</ResponseField>

<ResponseField name="schema_version" type="string">
  `1.1`.
</ResponseField>

<ResponseField name="created_at" type="string">
  Task creation time in ISO 8601 format.
</ResponseField>

<ResponseField name="prediction_short" type="string">
  Overall verdict: `no_ai`, `mixed`, `ai`, or `unsure`.
</ResponseField>

<ResponseField name="headline" type="string">
  Display headline: `No AI detected`, `AI Detected`, or `Unsure`.
</ResponseField>

<ResponseField name="prediction" type="string">
  Supporting explanation for display.
</ResponseField>

<ResponseField name="confidence" type="string | None">
  `Low`, `Medium`, or `High` when supplied; otherwise `None` or omitted.
</ResponseField>

<ResponseField name="detection_source" type="string">
  `model` for frame analysis or `c2pa` when validated content provenance determines the result.
</ResponseField>

<ResponseField name="version" type="string | None">
  Frame model ID `image-flash-1`, or `None` for a provenance-only result.
</ResponseField>

<ResponseField name="source" type="dict">
  `file_name`, `content_type`, `size_bytes`, `duration_ms`, `width`, `height`, and optional native `fps`. The uploaded video is not returned.
</ResponseField>

<ResponseField name="metadata" type="dict">
  Content provenance (C2PA), software, and camera metadata when available.
</ResponseField>

<ResponseField name="sampling" type="dict | None">
  Effective frame sampling rate in `fps`, or `None` when frame analysis was not used.
</ResponseField>

<ResponseField name="frames" type="list[dict]">
  Sampled frames with `frame_id`, `timestamp_ms`, and an image `result`. Frame predictions use `Human`, `AI Detected`, `Mixed`, or `Unsure`.
</ResponseField>

<ResponseField name="segments" type="list[dict]">
  Timeline segments with `id`, `range.start_ms`, `range.end_ms`, `prediction_short`, `prediction`, and `frame_ids`. Segment labels are `human`, `likely_human`, `unsure`, `likely_ai`, `ai`, or `mixed`.
</ResponseField>

<ResponseField name="fraction_ai / fraction_human / fraction_mixed" type="float">
  Duration shares from 0 to 1. Additional `fraction_unsure`, `fraction_likely_ai`, and `fraction_likely_human` fields are included when nonzero. All applicable shares sum to one.
</ResponseField>

<ResponseField name="frames_processed / total_frames" type="integer">
  On success, both equal the number of returned frames.
</ResponseField>

See the [video response example](/api-reference/video-detection#successful-response) for frame and segment entries.

### Media timeouts and errors

```python
from pangram import MediaTaskTimeout

try:
    result = client.predict_video("clip.mp4", timeout=60)
except MediaTaskTimeout as error:
    result = client.wait_for_video(error.task_id, timeout=600)
```

Prediction timeouts budget submission and polling. Polling intervals below 0.1 seconds are clamped to 0.1; values must be positive and finite. The SDK retries polling on temporary transport errors and HTTP 429/5xx responses, honoring numeric `Retry-After` delays. `MediaRequestError` exposes the HTTP `status_code` when available. File-opening errors use Python's normal exceptions.

Keep the accepted task ID after a timeout. Media submission does not support idempotency keys, and another submission can create another billable task. The SDK never automatically retries a submission.

### list_models()

List the detection models available to this API key.

```python
available_models = client.list_models()
# e.g., ["default", "pangram-4"]
```

The returned `list[str]` preserves server order and reflects both the account's entitlements and current model availability. Do not hard-code the catalog or assume every API key sees the same values.

Use one returned selector as the keyword-only `model` argument on text and bulk requests.

<Warning>
The `model` argument is temporarily optional for backward compatibility. Omitting it preserves the existing wire payload, selects Pangram's server default, and emits a `DeprecationWarning`. Pass `model="default"` or another value from `list_models()` in new code. The SDK will require explicit model selection after September 30, 2026.
</Warning>

### predict()

Classify text as AI-generated, AI-assisted, or human-written. `predict()` submits an async inference task, polls until the task completes, and returns the completed task payload.

```python
result = client.predict(
    text,
    public_dashboard_link=False,
    timeout=300,
    poll_interval=0.5,
    model="pangram-4",
)
```

**Parameters**

<ParamField body="text" type="string" required>
  The text to be classified.
</ParamField>

<ParamField body="model" type="string">
  Keyword-only model selector returned by `list_models()`. Pass `"default"` to follow Pangram's current default model.
</ParamField>

<ParamField body="public_dashboard_link" type="boolean" default="false">
  Whether to include a public dashboard link in the completed response.
</ParamField>

<ParamField body="timeout" type="float" default="300">
  Maximum number of seconds to wait for the async task to complete.
</ParamField>

<ParamField body="poll_interval" type="float" default="0.5">
  Number of seconds to wait between polling attempts. Values below `0.1` are clamped to `0.1`.
</ParamField>

**Returns**

A dictionary with the following fields after the task reaches `STAGE_SUCCESS`:

<ResponseField name="stage" type="string">
  Terminal async task stage. Successful responses return `"STAGE_SUCCESS"`.
</ResponseField>

<ResponseField name="text" type="string">
  The analyzed text returned by the model. Pangram 4 may normalize the submitted text before inference; window offsets refer to this value.
</ResponseField>

<ResponseField name="version" type="string">
  The model version used for this result (e.g., `"4.1"` or `"4.0"`). Minor versions can change within the selected model series.
</ResponseField>

<ResponseField name="headline" type="string">
  Classification headline summarizing the result.
</ResponseField>

<ResponseField name="prediction" type="string">
  Long-form prediction string describing the classification.
</ResponseField>

<ResponseField name="prediction_short" type="string">
  Short-form prediction string. Pangram 4 returns `"AI"`, `"Human"`, or `"Mixed"`.
</ResponseField>

<ResponseField name="fraction_ai" type="float">
  Fraction of text classified as AI-written (0.0–1.0).
</ResponseField>

<ResponseField name="fraction_ai_assisted" type="float">
  Fraction of text classified as AI-assisted (0.0–1.0).
</ResponseField>

<ResponseField name="fraction_human" type="float">
  Fraction of text classified as human-written (0.0–1.0).
</ResponseField>

<ResponseField name="num_ai_segments" type="integer">
  Number of text segments classified as AI.
</ResponseField>

<ResponseField name="num_ai_assisted_segments" type="integer">
  Number of text segments classified as AI-assisted.
</ResponseField>

<ResponseField name="num_human_segments" type="integer">
  Number of text segments classified as human.
</ResponseField>

<ResponseField name="dashboard_link" type="string">
  Dashboard link. Only present when `public_dashboard_link` is `True`.
</ResponseField>

<ResponseField name="windows" type="list">
  List of text windows and their classifications. Each window contains:

  <Expandable title="Window object properties">
    <ResponseField name="text" type="string">
      The window text.
    </ResponseField>
    <ResponseField name="label" type="string">
      Classification label. Pangram 4 returns `"AI-Generated"`, `"AI-Assisted"`, or `"Human Written"`.
    </ResponseField>
    <ResponseField name="ai_assistance_score" type="float">
      AI assistance score (0.0–1.0), where 0 means no AI assistance and 1.0 means AI-generated.
    </ResponseField>
    <ResponseField name="confidence" type="string">
      Confidence level (`"High"`, `"Medium"`, `"Low"`).
    </ResponseField>
    <ResponseField name="start_index" type="integer">
      Starting character index in the returned top-level `text`.
    </ResponseField>
    <ResponseField name="end_index" type="integer">
      End-exclusive character index in the returned top-level `text`.
    </ResponseField>
    <ResponseField name="word_count" type="integer">
      Number of words in the window.
    </ResponseField>
    <ResponseField name="token_length" type="integer">
      Token length of the window.
    </ResponseField>
    <ResponseField name="is_humanized" type="boolean">
      Whether Pangram 4's humanizer head classified the window as humanized. Present on every Pangram 4 window.
    </ResponseField>
    <ResponseField name="humanizer_score" type="float">
      Pangram 4 humanizer-head score from 0.0–1.0. Present on every Pangram 4 window.
    </ResponseField>
    <ResponseField name="class_probabilities" type="array">
      Pangram 4.1 posterior probabilities for Human, AI-Assisted, and AI-Generated, in that order (array of 3 floats). Present on Pangram 4.1 windows.
    </ResponseField>
  </Expandable>
</ResponseField>

Results remain normal dictionaries. Typed applications can import `PredictionResult` and `PredictionWindow` from `pangram`.

Raises `ValueError` if the API returns an error, the task fails, or the response is invalid. Raises `TimeoutError` if the task does not complete before `timeout`.

### submit_bulk()

Submit a Bulk API job for asynchronous AI detection across many inputs.

Provide exactly one of `text` or `items`.
Bulk jobs are processed asynchronously. Completion time depends on the number and length of submitted items and current system load. Use `get_bulk_status()` or `wait_for_bulk()` to monitor progress.

Use `text=[...]` for plain string inputs, or `items=[{"id": "...", "text": "..."}]` when you want customer IDs returned with status and results. Do not pass both.

```python
bulk = client.submit_bulk(
    items=[
        {"id": "row-001", "text": "First text to analyze"},
        {"id": "row-002", "text": "Second text to analyze"},
    ],
    model="pangram-4",
)

bulk_id = bulk["bulk_id"]
```

**Parameters**

<ParamField body="text" type="list[string]">
  List of input texts. Use this shape when you do not need customer item IDs.
</ParamField>

<ParamField body="items" type="list[dict]">
  List of item dictionaries. Each item must include `text` and may include a unique customer-defined `id`.
</ParamField>

<ParamField body="model" type="string">
  Keyword-only model selector returned by `list_models()`. Applies to the entire bulk job; per-item model selectors are not supported.
</ParamField>

**Returns**

<ResponseField name="bulk_id" type="string">
  The ID of the bulk job.
</ResponseField>

<ResponseField name="status" type="string">
  Initial status. Usually `queued`; returns `failed` if every item failed immediate validation.
</ResponseField>

<ResponseField name="total_items" type="integer">
  Total number of submitted items.
</ResponseField>

<ResponseField name="accepted_items" type="list">
  Items accepted for processing. Each item includes `index`, optional `id`, and `task_id`.
</ResponseField>

<ResponseField name="failed_items" type="list">
  Items that failed immediate validation. Each item includes `index`, optional `id`, `task_id: None`, `stage`, and `error`.
</ResponseField>

### get_bulk_results()

Fetch all available results for a bulk job.

```python
results = client.get_bulk_results(bulk_id)

for item in results["items"]:
    if item["result"] is not None:
        print(item["id"], item["result"]["prediction_short"])

for failed in results["failed_items"]:
    print(failed["id"], failed["error"])
```

**Parameters**

<ParamField body="bulk_id" type="string" required>
  The bulk job ID returned by `submit_bulk()`.
</ParamField>

<ParamField body="page_size" type="integer" default="1000">
  Number of submitted item slots to request per API call. The API allows up to `1000`.
</ParamField>

**Returns**

A dictionary containing `bulk_id`, `total_items`, `items`, and `failed_items` aggregated across every results page. Successful completed items include `result` with the same shape returned by `predict()`. In-progress items have `result` set to `None`.

`get_bulk_results()` materializes all pages into memory. For large jobs, use `get_bulk_results_page()` in a loop and process each page as it arrives.

The SDK returns this dictionary as `BulkResults`; successful item results use `PredictionResult`.

### get_bulk_results_page()

Fetch one paginated results page for a bulk job.

```python
page = client.get_bulk_results_page(bulk_id, offset=0, limit=100)
```

Use this when you need incremental page-level inspection before fetching or storing the full result set.

```python
offset = 0
limit = 1000

while True:
    page = client.get_bulk_results_page(bulk_id, offset=offset, limit=limit)
    for item in page["items"]:
        process(item)
    for failed in page["failed_items"]:
        handle_failure(failed)

    offset += limit
    if offset >= page["total_items"]:
        break
```

**Parameters**

<ParamField body="bulk_id" type="string" required>
  The bulk job ID returned by `submit_bulk()`.
</ParamField>

<ParamField body="offset" type="integer" default="0">
  Zero-based submitted-item offset.
</ParamField>

<ParamField body="limit" type="integer" default="100">
  Maximum number of submitted item slots to return. The API allows up to `1000`.
</ParamField>

**Returns**

A dictionary containing `bulk_id`, `offset`, `limit`, `total_items`, `items`, and `failed_items` for the requested page.

The SDK returns this dictionary as `BulkResultsPage`.

## Typed response contracts

The SDK ships a `py.typed` marker and exports its public `TypedDict` contracts from `pangram`:

```python
from pangram import (
    BulkResultItem,
    BulkResultMetadata,
    BulkResults,
    BulkResultsPage,
    PredictionResult,
    PredictionWindow,
)
```

| Type | Represents |
|---|---|
| `PredictionWindow` | One classified window, including optional Pangram 4 humanizer fields. |
| `PredictionResult` | A successful text prediction. |
| `BulkResultMetadata` | Status metadata shared by successful and failed bulk items. |
| `BulkResultItem` | Bulk item metadata plus its prediction when processing succeeds. |
| `BulkResultsPage` | One paginated bulk results response. |
| `BulkResults` | All bulk results pages aggregated by the SDK. |

The runtime values remain ordinary dictionaries and lists; these types provide static checking without changing existing access patterns.

## Deprecated Methods

<Warning>
The following SDK compatibility methods are deprecated and may be removed on August 1, 2026. Use `predict()` for one-off calls or `submit_bulk()` for asynchronous bulk jobs.
</Warning>

### predict_short() <Badge color="red">Deprecated</Badge>

Forwards to `predict()` and returns the current async result schema.

```python
result = client.predict_short(text, model="pangram-4")
```

### batch_predict() <Badge color="red">Deprecated</Badge>

Calls `predict()` once per input text. Use `submit_bulk()` for asynchronous bulk jobs.

```python
results = client.batch_predict(
    ["text one", "text two"],
    model="pangram-4",
)
```

## Removed Legacy Methods

`predict_extended()` and `predict_sliding_window()` are no longer part of the current `pangram-sdk`. Use `predict()` for current AI detection and segment-level results.
