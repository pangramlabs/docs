<Badge color="green">Current</Badge>

The Image API accepts one base64-encoded image, performs required safety checks, and returns an asynchronous task ID. Poll the task until it reaches `STAGE_SUCCESS` or `STAGE_FAILED`.

The production base URL is:

```text
https://image.external-api.pangram.com
```

<Note>
The Image API currently accepts one image per task. There is no public bulk-image endpoint.
</Note>

## Authentication

Send your Pangram API key in the `x-api-key` header on every request. A task can only be read using the same API key that created it.

## POST /v1/tasks

Create an image-detection task.

```text
POST https://image.external-api.pangram.com/v1/tasks
```

### Request

<ParamField body="image_b64" type="string" required>
  Base64-encoded image bytes, either as plain base64 or a base64 data URL. The decoded image can be at most 32 MiB. The complete JSON request body can be at most 128 MiB.
</ParamField>

Unknown request fields are rejected.

### Submit an image with cURL

```bash
base64 < image.png | tr -d '\n' \
  | jq -Rs '{image_b64: .}' \
  | curl -sS \
      -H 'content-type: application/json' \
      -H "x-api-key: $PANGRAM_API_KEY" \
      --data-binary @- \
      https://image.external-api.pangram.com/v1/tasks
```

### Submit an image with Python

```python
import base64
from pathlib import Path

import requests

image_b64 = base64.b64encode(Path("image.png").read_bytes()).decode("ascii")
response = requests.post(
    "https://image.external-api.pangram.com/v1/tasks",
    headers={"x-api-key": "your_api_key_here"},
    json={"image_b64": image_b64},
    timeout=30,
)
response.raise_for_status()
task_id = response.json()["task_id"]
```

Successful admission returns `202 Accepted`:

```json
{
  "task_id": "8db93921-df98-4edf-ae1d-8dd5839cd473"
}
```

## GET /v1/tasks/{task_id}

Fetch a task's current stage or completed result.

```bash
curl -sS \
  -H "x-api-key: $PANGRAM_API_KEY" \
  https://image.external-api.pangram.com/v1/tasks/8db93921-df98-4edf-ae1d-8dd5839cd473
```

### Processing response

```json
{
  "task_id": "8db93921-df98-4edf-ae1d-8dd5839cd473",
  "stage": "STAGE_IMAGE_INFERENCE"
}
```

Processing stages are `STAGE_IMAGE_SAFETY`, `STAGE_IMAGE_INFERENCE`, and `STAGE_IMAGE_FINALIZING`. Terminal stages are `STAGE_SUCCESS` and `STAGE_FAILED`.

### Success response

```json
{
  "task_id": "8db93921-df98-4edf-ae1d-8dd5839cd473",
  "stage": "STAGE_SUCCESS",
  "prediction": "Human",
  "ai_likelihood": 0.0002,
  "confidence": "High",
  "detection_source": "model",
  "version": "Pangram Image 0.2",
  "heatmap": {
    "grid": [[0.1, 0.9]],
    "patch_stride": 16
  },
  "metadata": {
    "c2pa": {
      "present": false,
      "validation_state": null,
      "claim_generator_info": null,
      "issuer": null,
      "actions": []
    },
    "software": [],
    "camera": null
  },
  "thumbnail": {
    "data_url": "data:image/jpeg;base64,<base64 JPEG>",
    "width": 256,
    "height": 171
  }
}
```

<ResponseField name="task_id" type="string">
  Server-generated UUID for the task.
</ResponseField>

<ResponseField name="stage" type="string">
  `STAGE_SUCCESS` for a successful result.
</ResponseField>

<ResponseField name="prediction" type="string">
  One of `AI Detected`, `Human`, `Mixed`, or `Unsure`.
</ResponseField>

<ResponseField name="ai_likelihood" type="float | null">
  Model score from 0.0 to 1.0. This is `null` when `detection_source` is `c2pa`.
</ResponseField>

<ResponseField name="confidence" type="string | null">
  `Low`, `Medium`, or `High`. This is `null` when `detection_source` is `c2pa`.
</ResponseField>

<ResponseField name="detection_source" type="string">
  `model` when the prediction comes from Pangram's image model, or `c2pa` when validated provenance determines the result.
</ResponseField>

<ResponseField name="version" type="string | null">
  Image model version. This is `null` for C2PA detections.
</ResponseField>

<ResponseField name="heatmap" type="object | null">
  Patch-level model scores in `grid`, with their input-pixel spacing in `patch_stride`. This is `null` for C2PA detections.
</ResponseField>

<ResponseField name="metadata" type="object">
  Extracted image provenance and capture metadata.

  <Expandable title="Metadata fields">
    <ResponseField name="c2pa" type="object">
      C2PA presence, validation state, issuer, claim generator, and declared actions. `validation_state` is `invalid`, `valid`, `trusted`, or `null`.
    </ResponseField>
    <ResponseField name="software" type="array">
      Software found in C2PA, EXIF, or XMP metadata. Each entry includes `name`, nullable `version`, `role`, and `source`.
    </ResponseField>
    <ResponseField name="camera" type="object | null">
      Camera make, model, capture time, and metadata source when available.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="thumbnail" type="object | null">
  A metadata-stripped JPEG thumbnail returned as `data_url`, plus its `width` and `height`. Its longest edge is at most 256 pixels, and images are never upscaled.
</ResponseField>

### Poll with Python

```python
import time

while True:
    response = requests.get(
        f"https://image.external-api.pangram.com/v1/tasks/{task_id}",
        headers={"x-api-key": "your_api_key_here"},
        timeout=30,
    )
    response.raise_for_status()
    result = response.json()
    if result["stage"] in {"STAGE_SUCCESS", "STAGE_FAILED"}:
        break
    time.sleep(0.5)
```

## Failed tasks

Failed tasks return a typed error. Safety-blocked tasks never expose model output, heatmaps, or thumbnails.

```json
{
  "task_id": "8db93921-df98-4edf-ae1d-8dd5839cd473",
  "stage": "STAGE_FAILED",
  "error": {
    "error": "The image could not be processed because it failed a safety check.",
    "error_code": "unsafe_image",
    "retryable": false
  }
}
```

Immediate request errors use the same `error` object without `task_id` or `stage`:

```json
{
  "error": {
    "error": "image_b64 must contain valid base64",
    "error_code": "invalid_request",
    "retryable": false
  }
}
```

Use `error.retryable` to decide whether retrying the request may succeed.

An image that passes request validation but cannot be decoded during processing can fail asynchronously with `error_code: "invalid_image"`.

## HTTP errors

| Status Code | Description |
|---|---|
| `400 Bad Request` | The request body or base64 value is invalid. |
| `401 Unauthorized` | The `x-api-key` is missing or invalid. |
| `402 Payment Required` | The account has insufficient credits. |
| `403 Forbidden` | The API key cannot access the requested task. |
| `404 Not Found` | The task does not exist. |
| `413 Payload Too Large` | The request or decoded image exceeds its size limit. |
| `422 Unprocessable Entity` | A required field is missing or the JSON body does not match the request schema. |
| `429 Too Many Requests` | The API key exceeds its configured rate limit. |
| `500 Internal Server Error` | The service encountered an unexpected error. |
| `503 Service Unavailable` | Image processing is temporarily unavailable. |
